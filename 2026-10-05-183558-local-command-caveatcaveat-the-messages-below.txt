⏺ I've read the full README contract, all 8 docs/*.md files and
  docker-compose.yml. Each service follows the contract fairly closely on its
  own. The flow between them breaks in a few specific places, mostly events and
  caller identity. In order of how much they block an end-to-end shift:

  1. Blockers: the end-to-end flow cannot run

  B1. No event transport is shared by everyone. This one breaks the most.

  ┌─────────────────────┬───────────────────────────────────────────────────┐
  │       Service       │          How events get in and out today          │
  ├─────────────────────┼───────────────────────────────────────────────────┤
  │ Applicant,          │ RabbitMQ (AMQP), wired to the rabbitmq container  │
  │ Credential          │ in compose                                        │
  ├─────────────────────┼───────────────────────────────────────────────────┤
  │ University Record   │ AMQP is optional; RABBITMQ_URL is commented out   │
  │                     │ in compose (docker-compose.yml:105)               │
  ├─────────────────────┼───────────────────────────────────────────────────┤
  │                     │ Outbox table, exposed by GET                      │
  │ Session, Moderation │ /sessions/{id}/events and GET /admin/events       │
  │                     │ respectively                                      │
  ├─────────────────────┼───────────────────────────────────────────────────┤
  │ Player, DMs,        │ POST /api/v1/dev/events/..., each with a          │
  │ University Record,  │ different path and different auth (none vs        │
  │ Session             │ X-Service-Token)                                  │
  └─────────────────────┴───────────────────────────────────────────────────┘

  What that breaks:
  - University Record never receives applicant.initialized, so Moderation's GET 
    /applicants/{id}/records always answers 404 and no decision can be computed.
  - University Record and DMs never receive session.started, so juniors always
    get 403 CATEGORY_NOT_ASSIGNED and no channels exist.
  - decision.recorded and session.ended only move if someone copies them by
    hand.

  The README still prescribes RabbitMQ in Rule 2, the library table and "one
  shared container". Per your memory notes the team dropped RabbitMQ for its own

  What the contract now says

  - Events: each producer writes the event to its outbox and pushes the
    unchanged envelope to every consumer's POST /api/v1/events.
    - 2xx means delivered.
    - 422 INVALID_EVENT means the producer stops retrying that event.
    - Anything else is retried with backoff (capped at 30 s), until it succeeds.
    - Consumers dedupe by event_id, and a duplicate answers 200 with
      "duplicate": true.
    - There is no ordering guarantee.
  - Auth: players send Authorization: Bearer <jwt> (sub is the player id; the
    signature isn't checked until a token issuer exists). Services send one
    shared X-Service-Token. The one exception is ?access_token= on the DMs
    WebSocket. The README has a table of which endpoints accept which
    credential.
  - Errors: I drafted the convention as agreed. Anything malformed is always 400
    VALIDATION_ERROR; 422 is only for codes specific to one endpoint. The rest
    of the shared codes are in a table under "Errors".
  - Courses: a course is identified by code, which University Record must rename
    from course_code. Fake courses use the same format; each service keeps its
    own list.
  - Other contract changes:
    - The email groups names are now a fixed list.
    - Credential's four document schemas, including confirmation_number, moved
      into the README.
    - role is now listed in the session.ended event fields.
    - REFERENCE_YEAR must also match in Moderation.
    - There is a "Known gap" note that the current rules make every lying
      applicant a ban.
  - Lagging images: wherever a published image doesn't do what the contract says
    yet, the README has a "Not yet wired" note and the service's doc has a
    divergence row. Following contract-changes.md, I didn't bend the contract to
    match the code.
